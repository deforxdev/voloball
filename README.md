# VOLOBALL

Приватний репозиторій проєкту волейбольної гри на Godot.

## Гілка `ios` — адаптація для iPhone

Це мобільна гілка. Робоча Windows-версія зберігається окремо в гілці `windows`.

Для iPhone додано горизонтальний екран, сенсорні стіки руху й прицілу, кнопки удару/стрибка/пасу/блоку/нирка/подачі, спавн м'яча, спринт, стійку, камеру, меню та зміну видимого рівня сили. Графіка починає з легкого профілю, 75% 3D-роздільності й обмеження 60 FPS. Управління враховує безпечну область екрана.

GitHub Actions у `.github/workflows/ios.yml` використовує macOS і Xcode, збирає iPhone ARM64 та пакує **непідписаний IPA для SideStore**. Apple ID, пароль, сертифікат і provisioning profile не потрібні для цієї збірки; SideStore виконує підписання на етапі встановлення.

Після успішної збірки: GitHub → Actions → iPhone IPA for SideStore → успішний запуск → артефакт `VOLOBALL-iPhone-SideStore`. Розпакувати завантажений ZIP та відкрити IPA у SideStore. Сертифікати й термін підпису керуються SideStore.

Запуск сенсорної версії у Windows для перевірки: Godot із аргументами `-- --mobile-preview`. Окремий тест: `test_mobile_controls.tscn` із тими самими аргументами. Перевірка на фізичному iPhone залишається окремим кроком.

### Виправлення запуску 0.1.1

Телефон запускається безпосередньо в меню через окремий екран завантаження. Обов'язковий редактор персонажа та заставка з 12 персонажами більше не запускаються перед грою. Фонове прогрівання всіх зачісок, портретів і тренувального корту вимкнено на телефоні; потрібний режим створюється при відкритті.

Сенсорний код коректно обробляє стартові сцени без ігрового стану. Типова арена обирається серед наявних ресурсів замість відсутнього `nationals.tscn`. Збереження профілів не скидаються.

Опція `test_simulator` додає перевірку застосунку в симуляторі iOS: перший запуск → зміна режимів 30/60 FPS, потім перезапуск із перевіркою того самого профілю. Вона вимкнена за замовчуванням через збої завантаження самого симулятора на CI. IPA зберігається перед цією перевіркою. Для симулятора використовується Intel-сервер через [обмеження офіційних бібліотек Godot 4.7.1](https://github.com/godotengine/godot/issues/122379); кінцевий IPA збирається для фізичного iPhone ARM64. Симулятор використовує Compatibility; пакет 0.1.2 для телефона також використовує Compatibility.

## Базова Windows-версія

Гілка `windows` зберігає робочий Windows-проєкт, включно з виправленнями керування м'ячем. Мобільна адаптація розвивається окремо в `ios`.

### Запуск

1. Відкрити `project.godot` у Godot 4.7.1 для Windows.
2. Натиснути F5 для запуску гри.
3. Поточний рендерер — Forward+; налаштування збережені в `project.godot`.

Проєкт відновлено з білда. Частина вихідних ресурсів відсутня, тому `.godot/imported/`, UID-мапи, `.assets/` і `.autoconverted/` навмисно збережені в Git. Не видаляти ці каталоги з цієї базової версії. Локальний стан редактора та кеш шейдерів виключені.

### Поточна поведінка м'яча

- G у практиці створює вільний м'яч на 2,6 м над персонажем.
- V повертає м'яч у руки для подачі; наступне V запускає подачу.
- Видима сила 1–3 запускає підкидання з мінігрою, вищі рівні — автоматичну подачу. Правило враховує налаштований максимум шкали, зокрема 9 і 10.
- Підкидання підвищене; повторна подача після падіння м'яча знову запускає мінігру.

### Перевірка

```powershell
& 'E:\Godot_v4.7.1-stable_win64.exe' --headless --path . --scene res://test_ball_controls.tscn
```

Тест перевіряє спавн, повторні подачі та видимі рівні сили для максимумів шкали від 3 до 16. Додатковий `test_mobile_controls.tscn` перевіряє багатопальцеве керування, відпускання дій, шкалу сили, мінігру та приховування настільних підказок. Перевірки проходять на Godot 4.7.1 у Windows і macOS CI.

## Android та iPhone

- Android: ARM64 APK збирається через Android LAN APK у GitHub Actions. Підпис тестовий; ключ зберігається в кеші CI.
- iPhone: сенсорне керування й CI-збірку IPA реалізовано; ціль перевірки на пристрої — iPhone 11 з iOS 26.6.2.
- Перевірити продуктивність, мобільний рендерер, розкладку інтерфейсу й залежності від настільних платформ.
- GitHub Actions використовує macOS із Xcode 26, без локального Mac і без секретів Apple. IPA призначений для iPhone з iOS 16+; запуск та продуктивність на фізичному телефоні потрібно перевірити після встановлення.

Джерела: [експорт Godot для iOS](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_ios.html), [SideStore FAQ](https://docs.sidestore.io/docs/faq).

Технічний огляд — у `ДОКУМЕНТАЦІЯ.md`.

## LAN і легке меню 0.1.2

На телефоні використовується окреме 2D-меню без арени, натовпу та моделей персонажів. Мобільний рендерер переведено в Compatibility, вимкнено натовп, фонові 3D-портрети та персонажа на екрані завантаження. Доступні економний режим (30 FPS, 60% 3D) і плавний режим (60 FPS, 75% 3D). Це зменшує навантаження; усунення вильоту на конкретному iPhone потрібно підтвердити на пристрої.

1. Підключити телефони до однієї Wi-Fi мережі або точки доступу. На iPhone дозволити локальну мережу.
2. Один гравець натискає «Створити кімнату» й повідомляє свій IP із меню.
3. Інші вводять цей IP і натискають «Підключитися».
4. Хост натискає «Почати матч». Розмір команд підбирається під гравців, максимум 5 × 5; порожні місця заповнює бот.

Порт UDP 28960. Максимум 10 людей разом із хостом. Хост обчислює матч і має залишатися на передньому плані. Окремий сервер та Photon не використовуються. Гостьові Wi-Fi з ізоляцією клієнтів можуть блокувати підключення. Для iOS додано опис дозволу локальної мережі, для Android — INTERNET.

`test_lan.tscn` перевіряє реальний ENet між окремими процесами: `-- --mobile-preview --lan-host --lan-count=10 --net-port 28973 --drive-role host` для хоста, ті самі аргументи без `--lan-host` для дев’яти клієнтів (окремий `--drive-role` кожному). Тест перевіряє склад матчу і передачу стану м’яча. Параметр `--lan-play` переходить у справжній матч для інтеграційної перевірки.

## Мобільний профіль матчу 0.1.3

Після повідомлення про виліт саме на «Почати матч» перевірено окремо створення 3D-сцени. Низька якість у 0.1.2 не забороняла створення GPU-шлейфів, stencil/contour-проходів, буфера віддзеркалень і тіньової сцени. Це були зайві ресурси; конкретну причину системного вильоту без iOS crash/Jetsam-журналу не встановлено.

Для мобільних пристроїв тепер використовується окремий легкий профіль існуючого Compatibility-рендерера: явно OpenGL ES на iOS, проста арена, однопрохідні шейдери персонажів/м’яча/підлоги/номерів, без stencil, GPU-шлейфів, віддзеркалень і тіньового атласу. Обличчя зменшено з 640×640 до 160×160, номери — з 256×256 до 128×128. Початковий режим — 30 FPS, максимум 60% 3D-роздільності. Анімації, фізика, керування та ENet залишаються в основному матчі.

Сцена матчу завантажується через окремий 2D-екран із прогресом і поверненням у меню. `mobile-diagnostics.log` зберігає етапи завантаження, рендерер і статичну пам’ять Godot. Кнопка «Скопіювати журнал запуску» у меню копіює його для повідомлення про збій. Статична пам’ять не дорівнює повній пам’яті процесу або GPU.

CI додатково перевіряє шлях меню → створення LAN-хоста → запуск матчу → 450 кадрів, а також відсутність активних GPU-шлейфів, віддзеркалювального viewport і contour-режиму. Опційна перевірка симулятора тепер виконує той самий шлях двічі, з перевіркою профілю після перезапуску. Перевірка на фізичному iPhone залишається необхідною.

### Статичне волосся на телефонах (0.1.4)

Під час додаткового аудиту знайдено, що `hair_physics = false` паркував уже створені SpringBoneSimulator3D, але не забороняв їх створення та CPU-перерахунок геометрії волосся/капелюхів. На телефонах ці етапи тепер пропускаються до виділення ресурсів. Волосся використовує статичну імпортовану форму; підгонка під нестандартні головні убори спрощена. Основний скелет персонажа й анімації збережені. Тест матчу додатково перевіряє, що SpringBoneSimulator3D не створено.
